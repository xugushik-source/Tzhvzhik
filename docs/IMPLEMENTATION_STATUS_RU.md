# Фактический результат · 15 октября 2026

Работа основана на `feature/tzhvzhik-demo` (`10be36b`). Для проверки и предотвращения возможной автопубликации результат сохраняется в отдельной `feature/tzhvzhik-operations`, PR направлен в demo-ветку.

## Реализовано в коде этой ветки

- `/admin/`: русский кабинет владельца; реальные D1 API заказов, поставщиков/ролей, групп, остатков, журнала и аналитики. Без пустых разделов для ещё не реализованных функций.
- Групповые callback Telegram больше не игнорируются. Личная привязка и действующая роль обязательны; чужой курьер не может забрать назначенный заказ. Поставщик видит только свои позиции. Данные поставщика не включают клиента/закупки других поставщиков.
- Независимая доступность/подготовка/готовность поставщиков. До звонка запрещена подготовка. До согласования точного состава/веса запрещена готовность. До готовности всех частей запрещены забор/выдача.
- Предложение замены без изменения заказа. Только покупатель с recovery capability принимает/отклоняет. Исходные позиции сохраняются, резервы перераспределяются атомарно, вес и сумма согласуются заново.
- Карточки Telegram с сохранением message_id и editMessageText; ошибки, время успеха, аренда обработки и экспоненциальные повторы. Очередь не отбрасывает старые неотправленные события.
- Подключение/проверка/отключение групп в кабинете. Личное приглашение поставщику теперь сохраняет его постоянный supplier ID.
- Складской журнал: приход, потери, инвентаризация; резерв нельзя списать. Приход обновляет средневзвешенную закупочную себестоимость. Снимки стоимости существующих заказов не переписываются.
- Расходы, проверенные частичные платежи, выплаты поставщикам и сдача наличных курьерами; защита от суммы сверх долга и повторной записи. Закрытие дня сохраняет снимок, не выполняет банковских операций.
- Серверная выручка/себестоимость/валовая прибыль, средний чек, день/7 дней/месяц по времени завершения, продажи по SKU и поставщикам. Закупки считаются отдельно от себестоимости продаж.
- Зеркало 12 листов Sheets: стабильные диапазоны, RAW, повтор без добавления дубликатов, очистка хвоста при сокращении списка, обновление OAuth access token по refresh token. Основные данные и история остаются в D1 при недоступности Google.
- Убрана синхронная отправка Telegram из ответа на сохранение заказа; внешний транспорт запускает Worker через waitUntil/cron.
- Исправлена ссылка серверных тестов на отсутствующую миграцию. CI дополнен запуском тестов.

## Проверки

`pnpm test`: 316 проверок (56 backend + 16 Telegram + 84 pairing + 90 meals + 44 client DOM stubs + 26 operations). Backend и operations используют настоящий SQLite через адаптер D1. Telegram/Google/R2 — имитаторы. Operations проверяет групповой webhook, его повтор, двух поставщиков, недоступность товара, согласованную замену, повторное взвешивание, готовность, доставку и отдельную оплату, обновление карточек, отказ транспорта, стабильный повтор Google, закупки/расходы/расчёты/кассу и повтор команды.

`pnpm build`: Wrangler dry-run прошёл. Это проверка сборки, не удалённое развёртывание.

Живой `/api/health` перед изменениями: HTTP 200, DEMO, storage=true, receipts=false, telegram=false. Публичный `/api/admin/orders`: HTTP 401. Health показывает наличие binding, но не доказывает запись в удалённую D1. Реальные заказы/клиенты/деньги не использованы.

Wrangler whoami: авторизации нет. Удалённые секреты не перечислены и не проверены. Браузерный E2E не выполнен: локальный Wrangler аварийно завершился на uv_interface_addresses; Chromium отсутствует, его загрузка возвращает повреждённый архив. DOM-тесты не выдаются за браузерную проверку.

## Незавершённая разработка — не блокируется авторизацией

- Нормализованное основное хранилище вместо ограниченного JSON store_state. Пока сохраняются лимиты 120 заказов/750 КБ; это DEMO, не готовая промышленная база. История/очереди больше не обрезаются молча, но при достижении ёмкости изменения отвергаются атомарно.
- Полноценные веб-аккаунты сотрудников и безопасные cookie-сессии. Сейчас новый кабинет предназначен для владельца с сервисным ключом.
- Полный набор разделов эталона: редактирование категорий/допродаж/промокодов; клиенты/спрос/брошенные корзины; закупочные заявки/перемещения/рекомендации; настройки уведомлений; детальный контроль курьеров. Не добавлялись фиктивные вкладки.
- Удаление позиции, изменение адреса/времени и количества с полным согласованием; сейчас замена поддерживает товар той же единицы измерения и повторное взвешивание.
- Структурированное предложение замены и указание времени подготовки прямо из Telegram-команд/кнопок. Сервер предложения и кабинет доступны, но полного Telegram-диалога ещё нет.
- Полный финансовый регистр для всех старых переходов approve_payment/collect_cash, возвраты и отклонённые/долговые операции, тарифы/вознаграждение курьеров, блокировка изменений закрытого дня. Снимок дня сейчас информационный, не бухгалтерское закрытие.
- Полная детализация Google-зеркала финансовых регистров и первоначальный OAuth consent в кабинете. Существующий адаптер покрывает перечисленные листы, но не все запрошенные аналитические показатели.
- Полные сценарии браузерного тестирования, доступность/мобильная визуальная проверка, полный обязательный 24-шаговый живой сквозной тест.
- Исключение дубля первоначальной Telegram-карточки при неоднозначном ответе внешнего API не гарантировано. Повторы бизнес-действий идемпотентны.

## Внешние блокировки

Нужен авторизованный Cloudflare для проверки D1, существования R2 bucket, секретов и развёртывания demo Worker. Изменять main/production без разрешения нельзя. Telegram: действующие токен/webhook secret и подключение настоящих тестовых групп. Google: OAuth consent и refresh token с доступом к выделенной таблице. Токены в чат/репозиторий не передавать.

Эталон Pivka клонирован только для чтения; изучены указанная структура админки, групповые приглашения, supplier/courier обработчики, сообщения и финансовые миграции. Пивные механики не переносились. Вторая база не подключалась.
