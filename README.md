# TZHVZHIK / ТЖВЖИК

DEMO-магазин мяса для Ахалкалаки. Опубликованная версия: https://javakheti-meat-demo.sacredfinch8.chatgpt.site

RU/KA/HY, 18 DEMO-товаров, корзина с очисткой/отменой, взаимные рекомендации, наборы. Заявка → звонок → фактический вес каждой позиции → согласование → поздняя оплата → тестовый чек → ручная проверка → выдача. Россия +15%, штучные бутылки и сыр, мясо с допуском ±200 г на строку. Реальные платежи и продажи алкоголя выключены.

## Запуск

Node >=22.13, pnpm 11.25.0, Python 3 для серверных тестов:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Адрес: http://localhost:5173. Независимый Worker использует локальные D1/R2 через Wrangler. Для сохранения заказов создайте игнорируемый `.dev.vars` с собственными случайными RECOVERY_SECRET и SERVICE_ADMIN_TOKEN. Значения опубликованного сайта не включены. Для локальной проверки API владельца используйте Authorization: Bearer с вашим SERVICE_ADMIN_TOKEN; внешний Worker удаляет недоверенные заголовки идентификации. Вход ChatGPT в интерфейсе кабинета работает на размещённом Sites; отдельному размещению нужен собственный вход. Telegram без секретов не подключён.

```sh
pnpm test
pnpm build
```

290 проверок магазина прошли до переноса: backend56 + Telegram16 + pairing84 + meals90 + client44. Telegram/R2 замоканы; SQLite настоящий. Это не браузерный E2E. Отдельный worker.mjs — адаптер запуска вне Sites; опубликованный сайт не изменён.

## Операционный кабинет (ветка feature/tzhvzhik-demo)

Новый кабинет: `/admin/`. Вход — существующий `SERVICE_ADMIN_TOKEN`; ключ хранится только в памяти вкладки. Это технический вход владельца, не полноценная система веб-аккаунтов сотрудников. Сотрудники выполняют разрешённые действия через личные привязки Telegram; групповая кнопка требует личной привязки и действующей роли.

Раздел «Telegram-бот»: сначала личное приглашение владельцу, затем поставщики/курьеры, затем групповое приглашение. Для группы владелец добавляет бота, будучи администратором группы, и выполняет `/connect <одноразовый код>`. Групповая ссылка сама по себе доступ не выдаёт. Для поставщика создайте роль с постоянным ID, назначьте этот ID товарам, подключите личный Telegram поставщика с тем же ID и отдельно его группу.

Worker отправляет уведомления после сохранения заказа через `waitUntil`; cron каждые 5 минут повторяет ошибки Telegram и Google. Telegram сохраняет ID карточки и редактирует её. Абсолютная гарантия exactly-once при потере ответа Telegram отсутствует: сбой после sendMessage до сохранения message_id может привести к повторной первоначальной карточке. Бизнес-команды защищены идемпотентностью и CAS.

Google: `GOOGLE_SPREADSHEET_ID`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN` через секреты Cloudflare; OAuth-разрешение Sheets на запись. Обновление access token автоматическое. `GOOGLE_ACCESS_TOKEN` — временная альтернатива только для тестирования. Вкладки создаются при первой успешной синхронизации, зеркало записывается по постоянным диапазонам с RAW, без append и формул из пользовательского ввода. Таблица должна быть выделена только для зеркала: синхронизация перезаписывает управляемые диапазоны. В репозиторий ключи не включать. Механизм получения первоначального OAuth consent/refresh token в интерфейсе ещё не реализован.

Чеки требуют R2 bucket `tzhvzhik-demo-receipts`, привязанного как `BUCKET`. Конфигурация подготовлена, существование bucket и его доступность удалённо не проверены. Сначала создать/проверить bucket в авторизованном Cloudflare. Не разворачивать конфигурацию вслепую.

Подробное состояние и невыполненные требования: `docs/IMPLEMENTATION_STATUS_RU.md`. Эта ветка не является заявлением о завершении всего задания. Main, production, DNS и исходный проект Pivka не изменялись этой реализацией.
